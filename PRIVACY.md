# Приватность

Мессенджер шифрует содержимое между конечными пирами, в том числе при передаче через реле. Он **не скрывает IP-адрес и не обеспечивает анонимность**. Это описание текущей реализации, а не результат независимого аудита безопасности.

## Какие данные видны

| Кому | Что видно |
|---|---|
| Прямому собеседнику | Сетевой адрес соединения, постоянный Peer ID, сообщения, подписи и время сообщений |
| Публичному узлу / каталогу | IP подключившегося клиента, Peer ID, публичный ключ, подписанный список объявленных адресов и срок регистрации; запрашиваемый при поиске Peer ID |
| Реле | Подключения и Peer ID участников, время, размеры и направление трафика; содержимое сообщения защищено конечным каналом |
| Сетевому провайдеру | IP, порты, время и объём трафика; WS без внешнего TLS раскрывает HTTP Upgrade и дополнительные метаданные протокола |
| GitHub при скачивании | IP и обычные метаданные HTTP-запроса к исходникам или релизу |
| Владельцу компьютера / резервной копии | Приватный ключ, история, очередь, контакты и настройки в каталоге профиля |

`localRoute()` берёт адреса из `host.Addrs()` без собственного фильтра: среди них могут быть адреса локальной сети, Docker, IPv6 и circuit relay. `publish()` отправляет подписанную запись известным кандидатам каталога. Подключённый пир также обменивается сетевыми сведениями через libp2p Identify. Поэтому очистка README не делает сетевую работу анонимной. [Спецификация Identify](https://github.com/libp2p/specs/blob/master/identify/README.md).

Каталог не требует списка ваших контактов или истории, но запрос `find` содержит искомый Peer ID. Постоянный ключ позволяет связывать сессии между собой. Смена IP не меняет Peer ID. Прямое пробивание NAT раскрывает адреса участникам; VPN/Tor и режим сокрытия адресов в приложении не реализованы. Один только выбор реле не гарантирует сокрытие адресов в регистрации и Identify.

## Что хранится локально

По умолчанию: `$XDG_DATA_HOME/p2pmessenger` или `~/.local/share/p2pmessenger`; `--data` выбирает другой каталог.

- `identity.key` — приватный ключ. Не публикуйте и не присылайте его.
- `state.json` — история и очередь **открытым текстом**, Peer ID, время, подписи и статусы.
- `config.json` — bootstrap, объявляемые адреса, пути сертификатов и параметры сети. Содержимое приватного TLS-ключа туда не копируется.
- `sequence.json` — версия регистрации; `node.log` — технические логи с адресами, Peer ID и ID сообщений. Сам текст сообщений штатно в лог не выводится.
- `peer-list-cache.json` — источник и последняя корректная копия списка публичных узлов. Это локальный файл профиля, исключённый из публикации.
- `control.sock` — локальное управление; `--status` выдаёт историю в JSON. Его вывод тоже нельзя публиковать без проверки.

На Unix создаются права 0700 для каталога и 0600 для файлов/сокета. В Windows доступ определяется также ACL; Unix-режимы не заменяют проверку прав Windows. Приложение не шифрует диск и не защищает от другого процесса с правами владельца.

Буфер обмена Windows читается только по явной команде вставки (F4 или полученные приложением Ctrl+V / Shift+Insert). Копирование в системный буфер выполняется по Ctrl+C, F3 или выбору элемента в F5. Содержимое буфера не опрашивается в фоне и не загружается на сервер: вставка создаёт локальный черновик, который отправляется отдельной командой пользователя. Другие приложения того же сеанса Windows могут читать системный буфер по правилам ОС. На Linux/macOS копирование через OSC 52 обрабатывает терминал, который также определяет поддержку и разрешения такого доступа.

## Скачивание и сетевые обращения

В исходниках приложения не обнаружены аналитика, загрузка истории разработчику, жёстко заданные внешние bootstrap-серверы или загрузка приватного ключа. По коду это адреса из сохранённых/переданных настроек и из libp2p discovery/Identify, проверки AutoNAT, маршрутизация через каталоги, реле и прямые каналы. NAT port mapping может обращаться к локальному маршрутизатору и пытаться создать отображение порта. Это проверка исходников и зависимостей по используемым API, а не полная трассировка всех возможных сетевых пакетов зависимостей.

Начиная с версии 0.2, без ручного bootstrap приложение по умолчанию получает `public-peers.txt` из `main` этого репозитория на GitHub при запуске и каждые 5 минут. GitHub видит IP и метаданные этих HTTPS-запросов. `--peer-list off` отключает загрузку; ручной `--bootstrap` также отключает автоматический общий список, если не задан явный источник. Для отдельной сети можно выбрать собственный файл/URL. Общий список проверяется на публичные адреса; явный пользовательский источник может содержать адреса локальной сети.

Для измерения RTT используется временный исходящий libp2p-узел с отдельным случайным ключом. Проверяемый сервер видит IP и временный Peer ID; постоянный ключ, история и подписанная регистрация основного узла в пробу не передаются. К выбранным узлам основной процесс подключается со своим постоянным Peer ID. Владельцы включённых в `public-peers.txt` узлов намеренно публикуют свои адреса и идентификаторы. Список доверен сопровождающим репозитория и их принятым PR; это не анонимная или децентрализованная система распространения начальных адресов.

Скрипты запуска обращаются к GitHub за бинарником и `SHA256SUMS`. Они не отправляют профиль и передают аргументы локальному процессу. Файлы загрузки удаляются после закрытия клиента; ключ и история остаются в профиле. Проверка SHA-256 обнаруживает повреждение/несовпадение загрузок, но не защищает при одновременной подмене бинарника и контрольных сумм в захваченном релизе. Для привязки к проверенной версии задайте `P2PMESSENGER_VERSION` и проверяйте источник запускающего скрипта.

## Перед публикацией

Не загружайте всю рабочую папку как ZIP. Публикуйте проверенный Git-репозиторий и артефакты `scripts/build-release.mjs`. Проверьте **все ветки и теги**, авторов и email коммитов, содержимое документации и архивов. `.gitignore` не удаляет уже закоммиченные данные из истории.

`node scripts/audit-publication.mjs --history` ищет некоторые типы ключей/токенов, профили, email внутри файлов, абсолютные пути, конкретные Peer ID и IP в рабочем дереве и достижимых коммитах. Имя и email автора в метаданных коммитов в этом проекте намеренно публичны и сохраняются. Дополнительный флаг `--private-authors` включает строгую проверку email авторов для других сценариев публикации. Проверка эвристическая: она не распознаёт все секреты, имена, пользовательские данные и форматы адресов. Она ничего не удаляет и не переписывает. Недостижимые Git-объекты и reflog в неё не входят; каталог `.git` не следует раздавать архивом.

Строки адресов в `public-peers.txt` — явное исключение из запрета публикации IP/Peer ID. CI дополнительно проверяет их формат и публичность через `--check-peers`. Проверки ключей, токенов и email в этом файле остаются включены. Другие файлы, включая документацию, по-прежнему проверяются на случайно опубликованные адреса.
